# Batch 21 - delaw: the German federal legal information portal API
# (Rechtsinformationsportal des Bundes, run by the Bundesministerium der Justiz
# and DigitalService).
#
# SCOPE. The tree carried de.openlegaldata.io - a volunteer scrape - and
# nothing from the German state's own legal information service. This is the
# official one: the BMJ's replacement for gesetze-im-internet.de and
# rechtsprechung-im-internet.de, serving federal legislation and the published
# case law of the five federal supreme courts as JSON-LD with ECLIs.
#
# WHAT THE API ACTUALLY ACCEPTS, established by probing rather than by reading
# documentation: `searchTerm` filters, and `pageIndex`/`size` page. `court`,
# `documentNumber`, `dateFrom` and `eli` are ACCEPTED AND IGNORED - a request
# carrying them answers HTTP 200 with the unfiltered collection and
# totalItems 10000, so a row written from the parameter list would have looked
# live and returned the wrong records forever. /v1/literature exists and is
# empty; /v1/administrative-regulation does not exist.
#
# pageIndex is ZERO-based, so every row declares page_zero_based=1. The
# `view.next` hypermedia link is a RELATIVE path, which is why these rows page
# arithmetically rather than through next_path.
#
# PAGING STABILITY, measured across ten pages of 100. Without an explicit sort
# the /v1/document search returns 965 rows carrying 963 distinct documents - the
# index reorders under the walk and repeats records. `sort=date` makes it
# 965 of 965, so the cross-search row declares it. The same fix does NOT work on
# the unfiltered /v1/case-law stream: sorted by date it returns 990 distinct of
# 1000 and unsorted 997 of 1000, because the date has too many ties. A row that
# structurally cannot walk its own collection without repeating was removed
# rather than shipped (DERIB_CASELAW_RECENT, in the rejects file); the
# searchTerm-filtered case-law row is stable and is kept.
#
