# Batch 21 - envreg: EPA Envirofacts tables the tree did not carry, as ENTITY
# PIVOTS rather than bulk head-of-table reads.
#
# SCOPE. The tree already reaches data.epa.gov/efservice for FRS, TRI facility,
# GHG and a handful of `rows/0:0` shape probes. What it did not carry is the
# whole SDWIS drinking-water model (public water systems, their facilities,
# their treatment trains, their violations, their enforcement actions and their
# lead-and-copper sampling), the TRI child tables behind a reporting form, the
# PCS/NPDES permit history tables, and the FRS cross-reference tables. Each
# table below was confirmed to exist by fetching it; the ones that answered
# `{"error": "<table>: The table is not available."}` are recorded as rejects
# rather than written from the data model documentation - rmp_facility,
# sems_active_sites, rcra_handler, icis_case, tri_submission and eleven others
# are documented Envirofacts tables that this REST service does not serve.
#
# PAGINATION. Envirofacts expresses the result window as a PATH segment
# (/rows/<start>:<end>), not as a query parameter, so there is no parameter for
# the engine to increment and every row declares `pagination_ok` saying so.
# Each row asks for rows 0:9999. Every keyed query measured here returned far
# fewer than that: the largest was violation/pwsid with 40 KB of records for
# one water system.
#
# TRAP measured here, and it is the one that matters: Envirofacts SILENTLY
# IGNORES a filter on a column the table does not have and answers HTTP 200
# with the unfiltered table. `tri_reporting_form/facility_name/CONTAINING/DOW`
# returns 10,000 records - the window cap - whose first record is byte-identical
# to the first record of the unfiltered table, because tri_reporting_form has no
# facility_name column at all. That row was written, probed PASS, and would have
# answered every query with the same ten thousand unrelated forms. It is now
# keyed on tri_facility_id, which was verified to filter (66 records for a real
# id, [] for a nonexistent one). Every other row's filter column was checked the
# same way: query a value that does not exist and confirm the answer is empty.
#
# REMOVED for cause: icis_facility_interest by facility name. A CONTAINING query
# on a common string returns 16.9 MB in 26 s and hits the 10,000-row window cap
# with no way to page past it, a BEGINNING query takes 36 s - past the engine's
# 30 s HTTP timeout - and one of the four measurement fetches came back as
# malformed JSON. Slow, capped and intermittently invalid is not a shippable
# row. It is in the rejects file.
#
# Columns: id|mode|want|category|record_type|tags|portal|name|name_ja|url|probe|description|opts
