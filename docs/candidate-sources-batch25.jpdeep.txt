# Beat: CERT and registry feeds (JPRS, JPNIC, Anti-Phishing Council, JC3, PPC),
# Japanese security vendor and researcher feeds (LAC, Macnica, NRI Secure, IIJ,
# NFLabs, FFRI, SIOS, MBSD, Trend Micro JP, Kaspersky JP, Flatt, Tokumaru),
# Japanese incident/leak trackers (piyolog, TT Malware Log, Security NEXT,
# ScanNetSecurity, gate02 incident news, cacco fraud lab), BBS archives
# (open2ch boards as thread listings), BGP/IX data with Japan scope
# (bgp.he.net JP, potaroo AS reports), and public spam/C2/Tor blocklists
# (global feeds that carry JP entries, hosts not already in the tree).
# Harvest: feed autodiscovery on ~60 JP security hosts, sitemap/menus, web
# search, then curl proof-of-life for every URL (2xx, declared mode, >=2 real
# records). Pivot rows were also asked about an impossible entity.
# Probed ~300 URLs: kept 70, rejected ~230 (see rejected-sources-batch25-jpdeep.tsv).
# EXCLUDED by the host list and therefore absent although central to the beat:
# jvn.jp, jvndb.jvn.jp, jpcert.or.jp, ipa.go.jp, nict.go.jp, nicter.jp, npa.go.jp,
# t.me, 5ch.net, web.archive.org, urlhaus/threatfox/openphish/phishtank,
# ransomware.live/ransomlook. Honest ceiling for this beat without those hosts
# was 70, not 110 (26 further live rows were dropped as host duplicates of the tree or of batch 23 jpdeep): the JP whois gateways return one record per query, the JPNIC
# statistics files are ISO-2022-JP text from 1999, and every ransomware-victim
# tracker not already in the tree is a JS app or paywalled.
