# Batch 32 — supplychain: software supply-chain and package-registry intelligence, cross-ecosystem.
#
# WHY THIS BEAT. The tree already carries package registries, but almost
# entirely as NAME SEARCH: "find me packages matching X". The three questions a
# supply-chain investigation actually asks were missing across every ecosystem:
#   * who can publish this thing (owners, teams, maintainer email)
#   * what has it published, when, and by whom (per-version history with the
#     publishing account and the artefact hash)
#   * what would break if that account were taken over (reverse dependencies,
#     namespace listings, the complete registry namespace as a denominator)
# Every row below answers one of those three for one ecosystem.
#
# PROVENANCE. Every endpoint here was fetched live with
# `curl -A "JapanOSINT/1.0"` from this session on 2026-10-04 (UTC), and every
# record count, field list and meta.total quoted in a description is what that
# body actually held at that moment. Nothing here is doc-derived.
#
# The pagination_ok notes are measured, not assumed: each paged row's page or
# offset parameter was requested a second time and the second response compared
# against the first. Three upstream limits found that way and recorded rather
# than papered over —
#   * crates.io REJECTS ?page= on /crates/{q}/versions (HTTP 400, "?page= is
#     not supported for this request") and returns the whole history instead;
#   * Docker Hub refuses anonymous paging past page 2 ("pagination offset too
#     large for anonymous requests"), so page_max=2 is the upstream's ceiling;
#   * npm's `from` is a record OFFSET, not a page number, so those rows declare
#     page_size=250 and page_zero_based=1 to make the engine step by 250 from 0.
#
