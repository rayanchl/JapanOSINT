# JapanOSINT — System-Wide Audit: iOS, Web Client, CI/Ops

*Scope: everything outside the C engine — `ios/` (148 Swift files, ~40k LOC), `client/` (57 files, 14,678 LOC), `.github/workflows/ci.yml`, `launch.sh`, `scripts/`, `.env.example`, `package.json`. The engine was audited separately and was not re-audited here, except where a client claim had to be verified against the server that produced it.*

*61 findings confirmed (1 critical, 4 high, 18 medium, 38 low). 8 candidate findings were investigated and refuted.*

---

## 1. Verdict

The engine's house rules were enforced in the engine and then dropped at the client seam. That is the single sentence that describes this surface.

The two clients are not equal. **iOS is genuinely disciplined**: zero `try!`, zero `as!`, zero force-unwraps across 148 files, zero `#Preview` blocks (so no fixture can leak into production by construction), every server decode going through `JSONDecoder` with errors wrapped rather than defaulted, and every mutation I checked (`AlertsTab.swift:136-217`, `CaseStore.swift:158-200`, `AlertInboxModel.swift:93-130`) implemented as optimistic-with-rollback that restores server truth. About a dozen iOS surfaces are *exemplary* on rule 2 and were clearly written by someone who understood it — `ExposureSection.swift:258` ("Showing N of M breaches"), `RulePreviewSection.swift:117/218` ("the scan cap was reached, so the true total is higher"), `TableBrowser.swift:265`, `GraphCanvasModel.swift:146-150`, `ExportSheet.swift:313-364`. The machinery exists, is correct, and is then not applied in roughly twenty other places in the same app.

**The web client is materially worse, and one finding in it is a rule-1 violation of the first order**: `client/src/hooks/useLiveVehicles.js` is a self-described *"Live-transit vehicle simulator"* that invents up to 25 vehicle positions per route and advances them at a hardcoded speed, mixes them into the same FeatureCollection as real GTFS positions, and renders both with the same icon under a toggle labelled "Trains & Subways". A user screenshotting that map as evidence is screenshotting invented data. Beyond that, the dominant web-client pattern is *fabricated negatives*: 12 of ~30 fetch call sites degrade a failure to `console.warn` or an empty value with no user-visible error channel, which turns HTTP 500s into confident factual statements — "Entity not found", "Total Sources 0 / Online 0 / Total Records 0" beside a pulsing live dot, "0/0 scheduled sources", and 174 layers that render identically whether they returned zero records or 500'd. There is no dev-only escape hatch anywhere in `client/` (`NODE_ENV`, `import.meta.env.DEV/MODE`: zero hits; no fixture assets; `client/public/` does not exist), so every one of these ships.

**CI/ops is the weakest link and the reason none of the above was caught.** CI runs 4 of `native/Makefile`'s 18 targets and gates almost nothing: the entire behavioural net for ~438k LOC of C is one unit-test file plus a selftest asserting "SQLite integrity ok and >80 schema objects". It never runs `make audit-sources` — and `audit-sources` itself scores only 30 of 1,239 files, exiting 0 while printing 146 unscored rule-2 findings, which makes CLAUDE.md's "The tree is at zero audit findings" true only of a 2.5% subset. CI touches neither `client/` nor `ios/` at all, despite both lockfiles being tracked and the vitest suite running green offline in 1.32 seconds. A syntax error in any of the 57 JS or 148 Swift files merges green today.

**Security**: storage hygiene is good — `.env` gitignored and never committed, `.env.example` 100% placeholders, iOS tokens in the Keychain, nothing sensitive in localStorage, no key-shaped literal anywhere in either client. The problems are all in transport and crypto: **there is no TLS anywhere in the system** (`mg_http_listen` on `http://0.0.0.0`, zero `mg_tls`/`SSL_CTX` hits), the shipping iOS default backend is a spoofable mDNS name over cleartext to which the Supabase bearer is stamped unconditionally, and `RAND_bytes` is called unchecked for the AES-256-GCM nonce protecting tenant API keys.

Where it is solid: iOS memory/optional safety, iOS mutation semantics, the ~12 exemplary disclosure surfaces in each client, secret storage, the auth gate itself (strict, fail-closed, should not be weakened), and `scripts/fetch-breach-corpus.mjs`, whose failure path stamps `origin: 'seed-fallback'` into its output so a degraded manifest is distinguishable from a live one — the correct pattern, in the one script nobody would have blamed for cutting a corner.

## 2. Confirmed findings

### CRITICAL (1)

#### C1. Map's moving trains, subways and buses are client-invented and visually indistinguishable from real GTFS positions
`client/src/hooks/useLiveVehicles.js:36`

**What.** Only `/api/transit/routes` (static geometry) is fetched (line 90). `spawnVehiclesForRoute` (36-64) invents up to `MAX_VEHICLES_PER_ROUTE=25` vehicles per route at fixed spacing, and the rAF loop (145-169) advances them at hardcoded `MODE_SPEED_MPS` (18-22: train 60 km/h, subway 40, bus 25). Invented vehicles (188-200) and real schedule-backed ones (202-215) are pushed into **one** FeatureCollection; only the latter carry `properties.schedule_backed = true` (line 212). `MapView.jsx:4388-4410` renders each mode through a single source/layer with one icon, so the two kinds are pixel-identical. The toggles read plainly "Trains & Subways" (`useMapLayers.js:973`) and "Buses" (`:991`). `grep -rn 'schedule_backed|simulat' client/src --include=*.jsx` returns **one** hit in the entire UI: the string "Not a schedule-backed vehicle" in `popups/VehiclePopup.jsx:11`, which appears only *after* the user clicks a marker. `MapView.jsx:4382-4383` concedes it in a comment: "data is client-generated". File line 1 self-describes as "Live-transit vehicle simulator". Ships in `client/dist`.

**Why it matters.** This is the purest form of the thing rule 1 exists to forbid: record-shaped content the server never produced, rendered with the same visual authority as observed data, on the platform's primary display surface. Anyone reading vehicle positions off this map — or capturing them as evidence — is reading a constant-speed animation.

**Fix.** Either stop emitting simulator vehicles and render only `schedule_backed` positions, or make the distinction unmissable in-band: tag simulator features `synthetic: true`, render them with a hollow/dashed icon via a MapLibre filter on that property, rename the toggle to "Trains & Subways (scheduled + estimated)", and add a legend line stating how many rendered vehicles are estimated vs schedule-backed. Both counts are already in hand at `useLiveVehicles.js:184`.

### HIGH (4)

#### H1. No TLS anywhere: server binds `0.0.0.0` in cleartext, shipping iOS client defaults to `http://`
`native/core/httpd.c:2532` · `ios/JapanOsintApp/BuildConfig.swift:24`

`snprintf(url, sizeof url, "http://0.0.0.0:%d", port); if (!mg_http_listen(&mgr, url, fn, NULL))`. `grep` for `mg_tls|MG_TLS|SSL_CTX|ssl_cert|MG_ENABLE_OPENSSL` across `native/core/*.{c,h}` returns **zero** matches — there is no TLS code path to switch on. Both iOS defaults are `http://` (`127.0.0.1` on macOS, `http://Rayans-MacBook-Pro.local:4000` on iOS); `Info.plist` sets `NSAllowsLocalNetworking=true`, which is what permits the cleartext `.local` load. `API.swift:91-97` stamps `Authorization: Bearer <supabase access token>` and `X-Tenant-Id` on every request over that channel, and `ApiKeyDetailView.swift:349-364` returns a **plaintext upstream API key** (Shodan, Censys, HIBP…) in a 200 body over it. The break-glass TOTP code traverses the same channel. I searched `docs/`, `launch.sh` and `.env.example` for any reverse-proxy/TLS-termination story (nginx, caddy, letsencrypt) and found none.

**Fix.** Terminate TLS in front of the C server and make the client refuse a non-`https` base URL for anything but loopback — validate the scheme in `AppSettings.backendBaseURL`'s setter and in the Connect field (`OnboardingFlow.swift:311`, `RootView.swift:324`), which today accept any string. Until then bind `mg_http_listen` to `127.0.0.1` by default with an explicit `JO_BIND=0.0.0.0` opt-in.

#### H2. A failed `/api/sources` fetch renders a complete, healthy-looking dashboard of zeros with a pulsing live indicator
`client/src/components/dashboard/SourceDashboard.jsx:71`

`if (res.ok)` with no else (70-82); the catch only `console.warn`s; `finally { setLoading(false) }` clears the spinner regardless. The early return at `:173` is `loading && !sources.length`, so once loading clears the full page renders with `sources = []`: a green `pulse-live` dot next to "Auto-refresh 30s" (`:189-191`), StatCards **Total Sources 0 / Online 0 / Degraded 0 / Offline 0 / Pending 0 / Total Records 0** (`:197-202`, fed by `statusCounts` `:97-105` and `totalRecords` `:166`), three empty recharts panels, and the table message "No sources match the current filters" (`:452-455`). The route-mounted path is identical: `App.jsx:194` passes `propSources`, and if App's `useDataSources` fetch fails, `propSources` is `[]` and `selfFetch` flips true — both paths land on the same all-zero render.

**Why it matters.** The screen's entire purpose is to answer "is collection healthy". It obtained nothing and answers with a specific, actionable, false operational picture: a platform monitoring 0 sources with 0 records, refreshing live.

**Fix.** Add an `error` state set on both the non-ok and catch branches; render it in place of the stat cards and table ("Could not load /api/sources (HTTP 503)"). Suppress the `pulse-live` indicator whenever the last fetch failed.

#### H3. `/api/follow/recent` returns an honest 501; the client converts it into a false empty-state sentence
`client/src/hooks/useCollectorFollowStream.js:105`

`httpd.c:1019-1020` replies 501 with the `miscapi.c:263-275` body, which carries a `detail` string and a comment explaining the deliberate not-implemented status. `useCollectorFollowStream.js:106` throws on `!res.ok`; `:112` swallows it with `catch { /* tolerable: stream will fill in */ }`. Neither the status nor `detail` reaches state — the hook exposes only `seeded` and `connected`. `FollowPanel.jsx:536-538` then renders: *"No collector traffic yet… the first cron tick will populate this stream."*

I verified the claim that sentence makes: `collector_request_hit`, `collector_run_start`, `collector_run_end` and `collector_hit_annotate` appear in **exactly one file in the entire repo** — `useCollectorFollowStream.js` itself. No native or server code emits them. No cron tick will ever populate this panel. A server-declared `not_implemented` was destroyed at the client seam and replaced with an invented causal explanation.

**Fix.** Keep the non-ok response: set `historyError` from `res.status` + the body's `detail`, and render "Request history unavailable: collector-tap history is not supported by the native server (501). Live stream only."

#### H4. Entity mention timeline shows 50 of a total the same component already displays
`client/src/hooks/useSearch.js:49`

`useSearch.js:49` hardcodes `?limit=50` and never sends `offset`. `EntityProfile.jsx:104-120` renders `mentions.map(...)` with no denominator, no pager, no "load more" — I read all 131 lines; there is no disclosure anywhere in the component. `profile.mention_count` is printed at `EntityProfile.jsx:61-63`, **40 lines above**. Server-side, `entityapi.c:551-560` accepts `offset` and supports `lim` up to 200, and `:584` is `LIMIT ?2 OFFSET ?3` — paging is implemented and unused. An entity with 3,000 mentions renders 50 rows and an analyst scrolling to the bottom reasonably concludes they have seen the complete history.

**Fix.** Render `Showing {mentions.length} of {profile.mention_count}` above the `<ul>` and add a "Load more" re-fetching with `&offset=${mentions.length}`.

## 3. House-rule compliance at the UI

### Do the clients fabricate anything?

**Yes — in both, and the two clients fabricate differently.**

**Positive fabrication (content the server never produced, rendered as findings):** two sites, and they are the loudest findings in this report.
1. `client/src/hooks/useLiveVehicles.js` — an explicit simulator producing invented vehicle positions on the map, indistinguishable from real GTFS. (**C1**)
2. `ios/…/OnboardingFlow.swift:479/542` — ten hardcoded intelligence findings, naming real collectors (SHODAN, JMA, AIS, GITHUB), under a `LIVE` badge, as the first thing every new analyst sees.

Everything else is worse-camouflaged but same-class:

**Negative fabrication (a failure rendered as a factual claim).** This is the dominant pattern and it is systemic in the web client — 12 of ~30 fetch call sites degrade to `console.warn` or an empty value with no user-visible error channel. It produces: "Entity not found — it may not have been extracted yet." (iOS **M1**), "No matching entities." / "No mentions." (iOS low), "Total Sources 0 / Online 0 / Total Records 0" beside a pulsing live dot (**H2**), "0/0" scheduled sources (**M4**), "0 cameras" (client low), a blank table pane (**M5**), "the first cron tick will populate this stream" for a route that returns 501 and never will (**H3**), and — affecting **all 174 map layers** — `useMapLayers.js:1471-1481` writing `{type:'FeatureCollection',features:[]}` into `layerData` on a caught fetch failure, with no `error` field anywhere in layer state and `LayerPanel.jsx:56-62` rendering nothing when `featureCount` is 0. ### The seam question: are `collector-truncation-notice` / `collector-status-notice` rendered anywhere?

**No. Not in one single place, in either client.** Verified two ways.

`grep -rn 'collector-truncation-notice|collector-status-notice'` over the whole repo returns 15 files, **all under `native/` and `docs/` — zero under `ios/` or `client/`**. And the mechanism by which they *could* render is independently broken in each client:

- The web SPA never calls any intel endpoint at all (`grep -rn 'api/intel|api/near|api/export|api/timeline|api/alert' client/src` is empty — its non-map surface is `/api/data/*`, `/api/search/*`, `/api/entities/*`, `/api/db/*`, `/api/status`, `/api/transit/*`, `/api/sources`), so a notice living in `intel_items` is unreachable **by construction**.

A notice therefore arrives in the Intel tab as an ordinary content row, visually identical to a real finding, and inflates that source's item count.

I traced a live example end to end. `native/collectors/sources/dam_water_level.c:64` emits a `collector-status-notice` reading *"collector not implemented — no request is spent until it can"*, `records_used: 0`. The web client has that layer (`useMapLayers.js:431`, `/api/data/dam-water-level`). So the honest server answer "this source is not implemented, and here is where its data would live" renders as a silent empty layer, pixel-identical to a source with zero records and pixel-identical to a source whose endpoint 500'd.

## 5. Checked and clean

Things I verified and found in good order. This list is as much a finding as the ones above — several of these are patterns the fixes should copy.

**iOS memory and type safety.** Zero `try!`, zero `as!`, zero force-unwraps of optionals across all 148 files. The only `fatalError` is the deliberate SwiftData one at `AppDataContainer.swift:22`. Zero `#Preview` blocks, so no preview fixture can leak into production **by construction**. GeoJSON geometry decoding (`Models.swift:104-135`) is fully defensive against malformed coordinates. `AuthTokenBox` correctly coalesces concurrent refreshes behind an `NSLock`, and `API.request()` (`:57`) does a single coalesced refresh-and-retry on 401 that **only replays GETs** (`:71`) — the right call.

**iOS mutation semantics.** Every optimistic mutation I checked snapshots and rolls back on server refusal with a visible error: `AlertsTab.swift:139/162/212`, `AlertInboxModel.swift:18/93-130`, `CaseStore.swift:157/158-200`, `CaseDetailView.swift:925`, `AOIListView.swift:197`.

**Honest-degradation exemplars worth copying.** `WidgetSnapshotBuilder.swift:46-49` — quake and warnings left empty *"intentionally left empty rather than fabricated"*, and `:55` preserves the last good snapshot rather than writing a blank one. `WebSocketClient.swift:36-45` — refuses to report "offline" for a dead push socket. `TrustBadge.swift:16-25` — keeps "we have no evidence" distinct from "we have evidence it is bad". `scripts/fetch-breach-corpus.mjs:74-84` — offline by default, and the failure path stamps `origin: 'seed-fallback'` into the output JSON so a degraded manifest is distinguishable from `hibp-live` and `seed`.

**Secret storage.** `.env` is gitignored (`.gitignore:3`), never committed (`git log --all -- .env` empty, `git ls-files --error-unmatch .env` fails). `.env.example` is 100% empty placeholders with no real-looking values. No key-shaped literal anywhere in `ios/` or `client/` except the correctly-labelled Supabase publishable key. iOS tokens are in the Keychain, never UserDefaults (I checked: UserDefaults holds only the API-timeout mirror, the layer-registry cache and collector favourites). The web client puts nothing sensitive in localStorage (theme, camera favourites, sensitive-layer consent only). Nothing logs a token or a key. CI receives no secrets at all — zero `secrets.*` references — consistent with its no-network stance.
