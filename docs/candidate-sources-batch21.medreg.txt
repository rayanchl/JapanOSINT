# Batch 21 - medreg: Health Canada's non-drug product registers.
#
# SCOPE. The tree carried fourteen health-products.canada.ca endpoints and all
# fourteen are the Drug Product Database. The Medical Devices Active Licence
# Listing (MDALL) and the Licensed Natural Health Products Database (LNHPD) run
# on the same host under different API roots and neither was reachable. A
# regulator's device register is the non-FDA equivalent of openFDA's device
# endpoints, which the tree does carry.
#
# TRAP measured here: the MDALL endpoints do not validate their query
# parameters. `/licence/?licence_id=66884` and `/licence/?original_licence_no=
# 66884` both return the ENTIRE 21 MB licence table with HTTP 200 - the unknown
# parameter is silently dropped rather than rejected. The parameters that
# genuinely filter are `licence_name` and `company_id` on /licence/,
# `licence_id` on /device/ and `company_name` on /company/, and each row below
# uses one that was proven to change the result set.
#
# REJECTED for cause under house rule 4b: the LNHPD `medicinalingredient`
# endpoint has NO unique column. Measured over 1,000 consecutive records, the
# most selective field (lnhpd_id) has 839 distinct values and every other field
# fewer, so any `id_keys` is a dimension rather than an identity and records
# collide across pages: the engine emitted 5,000 and stored 4,857 while the
# upstream itself served 4,997 distinct records. The row was written, run,
# measured and removed rather than shipped as a silent 3% loss.
#
