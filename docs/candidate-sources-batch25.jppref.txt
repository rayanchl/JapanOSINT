# Batch 25 - jppref: the 47 prefectural governments (都道府県庁) and their assemblies (県議会).
#
# How it was harvested (2026-08-29): every one of the 47 prefectural home pages was fetched and its
# <link rel=alternate> / href="*.xml|*.rss|*.rdf|/rss/" links were extracted; each prefecture's RSS index
# page was then read to enumerate the feeds it advertises; the same was done for all 47 assembly (議会)
# sites; open-data portals were located through the Qiita/awesome-japan-opendata registers and probed for
# CKAN / SHIRASAGI package_search; reiki (条例), e-nyusatsu (電子入札) and bousai (防災) portals were fetched
# and inspected for machine-readable endpoints. Every URL below was fetched with curl and returned HTTP 200,
# parsed in the declared mode and carried >= 2 real records at the time of the probe; the item count seen
# is stated in each description. Pivot rows were additionally asked about an impossible entity (zzqxv9).
#
# Probed 361 URLs. Kept 110. Rejected 251 (see docs/rejected-sources-batch25-jppref.tsv): 31 DUPLICATE_URL
# already in the tree, 102 DEAD, 15 EMPTY_RESULTSET/THIN, 8 BOT_WALL, 1 FILTER_IGNORED, 94 NOT_RECORDS
# (JS map apps, HTML-only portals, reiki menus, e-tender front pages, an object-keyed JSON with no array).
#
# What the beat could NOT yield as machine-readable rows: reiki (条例) databases are all behind g-reiki.net /
# d1-law.com which answer 403 to non-browser clients or are frame-based HTML; every prefectural e-tender
# portal is a login/JS front; every bousai portal (dis_portal, salesforce-sites, bodik maps) is a JS map
# with no discoverable JSON. Prefectural open data outside Kanagawa and Tottori is either already in the
# tree (Akita, Aomori, Gifu, Shizuoka, Kagawa, Tokushima, Ehime, Yamaguchi, Hokkaido/HARP, Miyazaki, Tokyo)
# or lives on data.bodik.jp (excluded host, and 403 to curl anyway) or is a static HTML page of CSV links.
# So the weight of this batch is press-release / tender / disposition / assembly RSS, which is what the
# prefectures actually publish as feeds - 44 of 47 prefectures are represented.
#
# Pipe-delimited. Columns: id|mode|want|category|record_type|tags|portal|name|name_ja|url|probe|description|opts
#
