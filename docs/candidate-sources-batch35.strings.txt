# Batch 35 — strings: four reachable endpoints whose records are bare JSON STRINGS.
#
# docs/rejected-sources-batch34.tsv claimed these were unregisterable, on the
# reasoning that lib/hpengine.c counts a bare scalar in a JSON array as an
# `empty` slot. That reading of the engine was WRONG and this manifest is the
# correction: hp_json_flat() already maps a non-empty JSON string to
# {"value": "<the string>"}, so `title_keys=value;id_keys=value` is all a
# string-array row needs. The `empty` path is for a NULL, a number or an empty
# string — a trailing newline, not a name.
#
