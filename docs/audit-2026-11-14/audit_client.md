- Client-side silent caps: `searchStore.js:45` keeps only 30 completed runs; `AdminPage.jsx:618` breach-id suggestions `slice(0,25)`; CameraDiscoveryThread `slice(0,12)` filter chips; IntelItemRow tags `slice(0,6)`; EntityGraph EDGE_LIST_CAP. - Hardcoded lists that can drift: `hooks/layerDefinitions.js` has 237 hand-written layer entries (endpoint `/api/data/<slug>`); any whose slug matches no server layer id is `clientOnly` and fetched from the legacy `/api/data/<slug>` (useMapLayers.js:256); `layerCatalog.js:16` CATEGORY_ORDER and CATEGORY_COLORS (unknown categories are appended, not dropped: OK). The registry itself is not hardcoded anywhere: sources, collectors, groups, facets come from the server.
- Map mapping: map layers come from `/api/layers` (layers.def curated + declared + generated `rt-<record_type>` / `unassigned-geocoded`, dataapi.c:330-440). A source appears on the map **only if it stores intel_items with `lat IS NOT NULL`**; every geocoded row is reachable via exactly one layer. Never on the map: sources whose records carry no coordinates (most RSS/CSV/statistics feeds), pivots with no stored results, pods. The geocoder pod can raise `awaiting_geo` rows later. The site never tells a user which layer a source feeds (WEB-09) and the layer panel gives only a source *count* (LayerPanel.jsx:193-199), not names or links.

## 4. Direct answers to the owner's question ("every collector / source usable in the site")
1. **Discoverable:** yes. All ~61.5k sources, ~640 collectors and the 23 groups are reachable via server-side search/facets/paging (/console/sources, /console/collectors). Two bounded facets (WEB-08).
2. **Inspectable:** yes, with notices, health reason/remedy, schedule, credentials (SourceDetailPage). Older run history unreachable (WEB-04).
3. **Scheduled feeds:** usable (view, run, tune). Run button visible to people who cannot run (WEB-06).
4. **Entity pivots:** NOT usable from the site except via the LLM router at /search. A "Run now" on a pivot succeeds with zero output (WEB-01). No direct entity input, no semantic finder in the UI (WEB-07); the server has no entity parameter either.
5. **Maintenance pods:** visible as `internal` rows/collectors; run correctly disabled; their outputs appear in Admin maintenance lists (AdminPage.jsx).
6. **Map:** only sources that store geocoded records can ever appear; the site does not say so or show which layer a source feeds (WEB-09).
7. **Scale risk:** five screens still pull the whole registry (WEB-03, WEB-05); these are the first things that will break at 61k sources.
